# Chiller: подробности использования

Обзор, скриншоты и быстрый старт — в [README](../README.md). Здесь собраны детали: ключи, данные, сборка, провайдеры, вложения, история и ограничения.

## Ключи и локальные данные

API-ключ не вставлять в репозиторий, документацию, тестовые fixtures или сообщения субагентов. Для первого opt-in live test предполагается переменная `DEEPSEEK_API_KEY`, затем хранилище секретов ОС / ввод на время сессии в приложении. Общие тесты выполняются без ключа через FakeProvider и fixtures. Отсутствие ключа не должно блокировать сборку и разработку UI.

## Сборка и запуск

JDK 21+ (текущая проверка на JDK 26), Gradle 9.4.0 через wrapper, Kotlin 2.3.21, Compose 1.10.3. Для файлового поиска нужен `rg` на PATH; сквозной offline smoke также использует Python 3. Первый запуск скачивает JVM/Compose-зависимости, включая нативный runtime текущей ОС.

```sh
./gradlew check :evals:offlineSmoke
./gradlew :evals:liveDeepSeekSmoke   # opt-in, нужен ключ и небольшой бюджет
./gradlew :app-desktop:run
```

В приложении выберите папку проекта, настройте URL/model/API key. Ключ из UI действует до выхода; кнопкой «Запомнить ключ» в настройках подключения его можно явно сохранить в Keychain (macOS) или Диспетчер учётных данных Windows. Без ключа доступен явно обозначенный offline-режим; он не выполняет задачи пользователя с файлами. По умолчанию выбран Plan. Изменения файлов разрешаются в Workspace edit, запуск команд — отдельным переключателем; это не OS sandbox.

По умолчанию данные приложения сохраняются в `~/.chiller`; `CHILLER_DATA_DIR` позволяет выбрать отдельную папку. В настройках на диск записываются URL/model/workspace и ссылки на origin сохранённых ключей, но не сами ключи. Для изолированного просмотра:

```sh
CHILLER_DATA_DIR="$PWD/.chiller/local" ./gradlew :app-desktop:run -PchillerPreview=true
```

Общий `check` не использует удалённую модель. `offlineSmoke` выполняет scripted model loop с настоящими файловыми операциями, Python-проверками и восстановлением журнала. DeepSeek проходил ограниченные live-проверки на предыдущем checkpoint; новые возможности проверены offline. Gemma 4 26B A4B на vLLM проверена небольшими live-прогонами (см. README). CI проверяет unit-тесты на трёх ОС и сборку DMG/MSI; это не заменяет ручную приёмку установки и интерфейса.

В меню «Файл» доступны экспорт Markdown/JSON с предпросмотром и выбор рабочей папки через системный диалог. Экспорт скрывает известные поля секретов и приватное replay-содержимое; произвольный текст следует проверить вручную. Файлы артефактов представлены ссылками, а не встроенными копиями.

Контекст ограничивается целыми ходами пользователя с сохранением пар вызовов/результатов инструментов. Старые крупные tool-результаты под давлением заменяются короткой заглушкой, а не выбрасываются вместе с ходом. Оценка токенов приблизительная и учитывает письменность текста, JSON инструментов и резерв на изображения. После ответа индикатор показывает фактический вход последнего запроса, если провайдер сообщил его (без знака ≈); до ответа — оценку. Это не сумма расходов за чат. Фактический суммарный usage хода пишется в `run.summary`.

Инструменты спроектированы под минимум раундов: `read_file` отдаёт `snapshot_id`, успешный `edit_file` возвращает `snapshotId` новой версии, поэтому повторные правки одного файла не требуют перечитывания; независимые READ-вызовы выполняются параллельно, а эффекты — строго по порядку; `search_text` отдаёт компактные `path:line` с опциональным контекстом. `run.summary` в журнале фиксирует раунды, число и ошибки tool-вызовов, время и токены — по нему измеряется скорость, а не по ощущениям.

При запуске из корня репозитория приложение читает `API_TOKEN` из локального `.env` (также поддерживается `DEEPSEEK_API_KEY`). Переменные окружения имеют приоритет над файлом. `.env` исключён из Git. Файл читается при запуске; после изменения перезапустите приложение. При запуске через Finder рабочая папка может отличаться: для `.env` используйте команду Gradle из корня проекта. Ключ из UI остаётся в памяти; его можно явно сохранить в Keychain (macOS) или Диспетчер учётных данных Windows отдельной кнопкой.

Флаг `-PchillerPreview=true` собирает отдельный `ChillerPreview.app` и полностью отключает автоматическую загрузку ключа при запуске — для безопасной визуальной проверки. Обычная сборка: `./gradlew :app-desktop:createDistributable`.

В ответах сохраняется автор модели; старые сообщения имеют нейтральную подпись, offline — отдельную. Доступны меню моделей и истории, переименование, экспорт выбранного диалога, обычная/компактная плотность и постоянные настройки вида. Кнопка проверки подключения выполняет один ограниченный запрос только по нажатию; наличие ключа само по себе не означает проверенное соединение. При смене адреса провайдера используется ключ этого адреса (если он задан), ключ другого адреса туда не отправляется.

## Провайдеры и ключи

В «Настройки → Подключение» есть готовые провайдеры (совместимые с OpenAI Chat Completions): DeepSeek, OpenAI, OpenRouter, Google Gemini, Groq, Mistral, xAI, Together, Fireworks и локальные Ollama, LM Studio, vLLM. Ключ хранится отдельно для каждого адреса и уходит только туда; при запуске подхватываются переменные окружения или `.env`: `DEEPSEEK_API_KEY`/`API_TOKEN`, `OPENAI_API_KEY`, `OPENROUTER_API_KEY`, `GEMINI_API_KEY`, `GROQ_API_KEY`, `MISTRAL_API_KEY`, `XAI_API_KEY`, `TOGETHER_API_KEY`, `FIREWORKS_API_KEY`. Локальные серверы на `localhost` работают без ключа. Вживую проверен только DeepSeek.

## Версии, CI и релизы

Версия задаётся одной строкой `chillerVersion` в `gradle.properties` (формат `MAJOR.MINOR.PATCH`, `MAJOR > 0` — требование установщиков). Она попадает в jar-файлы, DMG/MSI и в «Настройки → О программе» вместе с коммитом сборки.

- `.github/workflows/ci.yml` — на каждый push в `master` и pull request: `check` на Linux, macOS и Windows (offline smoke — на Linux/macOS, ему нужен `python3`), затем DMG и MSI как артефакты сборки.
- `.github/workflows/release.yml` — тег `v1.2.3` собирает установщики с этой версией и прикладывает их к GitHub Release.

```sh
git tag v1.2.0-rc.1 && git push origin v1.2.0-rc.1   # release candidate: pre-release
git tag v1.2.0 && git push origin v1.2.0             # stable release
```

Установщики пока не подписаны: на macOS первый запуск — правый клик → «Открыть», на Windows SmartScreen может попросить подтверждение.

Правила визуальной проверки: [DESIGN.md](DESIGN.md).

Лимиты задачи настраиваются в «Настройки → Агент» и применяются со следующего сообщения: шаги модели, логические запросы и выходные токены на всю задачу (основной агент вместе с помощниками), длина ответа за шаг. У каждого есть вариант «Без лимита» («Максимум модели» для длины ответа: предел узнаётся из ответа провайдера и запоминается). Это не денежный лимит и не счётчик транспортных повторов. Независимо от настроек задача останавливается через 10 минут и после 500 шагов; её можно продолжить кнопкой «Продолжить».

Если ответ упирается в лимит длины, обрезанный вызов инструмента не выполняется: агент получает размер лимита и дописывает файл частями. Задача останавливается только после двух таких обрывов подряд без продвижения. Для постоянного хранения на macOS: «Применить», затем «Сохранить текущий ключ в Keychain»; изолированный нативный smoke create/reopen/update/delete с синтетическим ключом пройден на macOS.


## Файлы, интернет и история

- `create_file` безопасно создаёт недостающие родительские папки; `create_directory` доступен отдельно. Все пути остаются в выбранном workspace, симлинки и существующие файлы не подменяются.
- Cmd/Ctrl+V и перетаскивание добавляют текст, файлы или изображения. Вставка текста свыше **5120 байт UTF-8** становится `.txt`-вложением. До восьми вложений, файл до8 MiB, вставленная PNG до4 MiB/16 MP; импорт хранится в данных Chiller, не в проекте. Отправка ждёт завершения импорта. При переключении чата вложение остаётся у исходного диалога.
- Текст вложений модель читает через `read_artifact`: частями (`offset`/`limit`, ответ сообщает `next_offset`) или поиском `query`, который возвращает совпавшие строки с номерами и смещениями. Изображения (PNG/JPEG) уходят модели как vision-вход, если модель их понимает: «Настройки → Агент → Профиль модели → Изображения» (Авто — по `input_modalities`/`capabilities` каталога, иначе по ID модели: DeepSeek Flash, Gemma 3/4, GPT-4o, Qwen-VL и др.; Вкл; Выкл). Картинка уменьшается до 1568 px по длинной стороне и перекодируется в JPEG; отправляются только картинки двух последних сообщений пользователя, не больше четырёх за запрос. Иначе модель получает только имя, тип и размер файла. Вживую проверено на `deepseek-flash`: `./gradlew :evals:liveVisionSmoke` отправляет картинку со случайным числом и проходит, только если модель его прочитала (2/2, 265 входных токенов, ~1.3 с). На Gemma 4 26B A4B (vLLM за шлюзом) проверка тоже пройдена (~1.3 с). Если у провайдера есть модель изображений, `generate_image` рисует картинку по описанию или правит картинку проекта/вложение и сохраняет результат новым файлом с превью и откатом (только в режиме «Изменения», не больше четырёх за ход); модель для картинок выбирается в «Настройки → Агент». `show_file` выводит карточку существующего файла; PNG/JPEG имеют ограниченный предпросмотр, остальные файлы можно показать в Finder/проводнике.
- В «Настройки → Агент» отдельно включается интернет: `web_search` (DuckDuckGo) и `web_fetch` (HTML/текст/JSON). Поиск может получить challenge от сервиса. Приватные адреса блокируются проверкой DNS, но это **не сетевой OS-sandbox**.
- На macOS снимок доступен только для окна, явно выбранного в настройках, после разрешения записи экрана в macOS. Модель не может сама выбрать другое окно; полного снимка дисплея нет. Windows/Linux capture пока не поддерживается.
- Диалог можно переименовать и удалить через меню истории. Удаление требует preview/подтверждения и не затрагивает проект; выбранный/активный диалог сначала нужно закрыть. Сообщение удаляется вместе с целым ходом, чтобы не разорвать пары tool-вызовов. Редактирование сохраняет новый текст и убирает последующие ответы, без автоматического запуска модели. Это не отменяет уже выполненные изменения файлов.
- Удаление/редактирование сообщений логическое: исходный append-only журнал сохраняется. Markdown экспортирует видимый разговор; JSON явно экспортирует исходный журнал, включая логически удалённые записи. Полное удаление данных диалога — отдельная операция.
- После прерванного действия доступно явное «Проверить и продолжить»: неопределённые результаты отмечаются UNKNOWN; команды автоматически не повторяются.

Дополнительные проверки выполняются только явно: `./gradlew :tools:webSmoke` (публичные фиксированные страницы, без ключей/проекта) и `./gradlew :app-desktop:keychainSmoke` (одноразовая синтетическая запись). Обычный `check` не вызывает платные API и интернет.

## Разрешение macOS на снимки окна

В настройках агента включите «Снимки окна» и нажмите «Обновить» в выборе окна: Chiller запросит системное разрешение на запись экрана. Если доступ уже отклонён, включите Chiller в «Системные настройки → Конфиденциальность и безопасность → Запись экрана и системного аудио» (название зависит от версии macOS). При необходимости перезапустите приложение, обновите список и выберите окно. Разрешение ОС и разрешение снимков внутри Chiller — отдельные настройки.

Запрос доступа запускается пользовательским выбором окна; модель сама не вызывает системный запрос. Для стабильного назначения разрешения используйте собранное Chiller.app; запуск из Gradle/терминала может отображаться в macOS под именем запускающего процесса.

Выбор «Команды процессов» сохраняется после перезапуска приложения. Он действует только вместе с режимом «Изменения»; режим «План» по-прежнему запрещает процессы. При открытии диалога лента начинается с последних сообщений; ручная прокрутка вверх отключает следование новым сообщениям.

## История и сокращение контекста

Бюджет запроса берётся из окна выбранной модели в каталоге, максимум 1 048 576 токенов. Если окно неизвестно, используется явно показываемый fallback 32 768. Из бюджета вычитаются резерв ответа, схемы инструментов и запас на протокол. Число в каталоге не доказывает, что сервер действительно разрешает такой запрос; оценка не заменяет токенизатор.

Отмена хода с уже полученными результатами инструментов не отсекает прежний план. Вызовы с неизвестным исходом по-прежнему требуют восстановления; операции не повторяются автоматически.

При нехватке места старые большие результаты заменяются заглушками; если этого недостаточно, исключаются целые старые ходы. Перед исключённой историей отправляется сохраняемая в `context.summary` сводка: выдержки недавних запросов, последнего подробного запроса и плана, ответы и ссылки на успешные файловые инструменты. Она пересобирается по действующей истории с учётом редактирования/удаления. Это ограниченная автоматическая выдержка, а не LLM-суммаризация: длинные цитаты обрезаются, семантическая полнота не гарантируется, дополнительных API-расходов нет. Исходная переписка сохраняется в журнале.

Над полем ввода видны числа исключённых сообщений и сокращённых результатов. Оценки, фактический вход и окно сохраняются в журнале и восстанавливаются при открытии сессии. Если текущий ход сам по себе не помещается после сокращения старых результатов, Chiller завершает запрос с ошибкой лимита, а не отправляет неполную пару инструмента.
