## Приоритетные исправления

1. **P1 — первичная настройка провайдера через discovery.** `SettingsPage.kt:121–152`: новый пресет без defaultModel очищает модель; список доступен только после применения endpoint, но Apply требует непустую модель. Получается круговая зависимость: пользователь должен знать ID вручную. Разрешить загрузку каталога для draft endpoint/key либо сохранить соединение без модели и блокировать только отправку.
2. **P1 — последовательность управления помощниками.** `SubagentTools.kt:70–72` помечает lifecycle как READ, а `AgentCoordinator.kt:356–369` параллелит READ. В одном batch wait может выполниться до spawn и сразу вернуться при пустом списке. Управляющие операции должны исполняться упорядоченно, независимо от разрешения Plan mode.
3. **P1 — приём mailbox на границе последнего раунда.** `SubagentSupervisor.kt:115–123,183–186`: проверка оставшихся раундов, drain inbox и обновление номера раунда не атомарны. Сообщение может быть принято после drain и перед переходом в последний раунд, но не обработано. Нужен общий mutex-переход и регрессионный тест.
4. **P2 — завершение диалога.** Устранить гонку из полного прогона тестов: новая сессия сразу после visible completed не должна молча игнорироваться.
5. **P2 — общий бюджет.** Есть ограничения на каждого помощника, но нет общего parent+children token/request budget. Для долгой автономной работы это существенный пробел.
6. **P2 — хранение ключа.** Ключ из UI остаётся только в памяти процесса; это нужно явно объяснять до закрытия приложения. Для постоянного хранения нужен системный credential store. Наличие ключа не равно проверенному соединению.

## Дизайн: точечная полировка

Основа стала гармоничнее: нейтральные поверхности, спокойный акцент, связанная группа mode/model и полезная Studio. Переписывать стек не требуется.

- Лента инструментов всё ещё слишком высокая: в показанном диалоге чтение, короткое пояснение и следующая операция занимают отдельные широкие блоки. По умолчанию сворачивать завершённую фазу в одну строку; ошибки, вопросы и результат оставлять заметными.
- В composer отдельная строка папки снова увеличивает высоту. Объединить контекст в компактный ряд, поле растить только от текста; сохранить удобные hit targets.
- В демо composer показывает DeepSeek и «нет ключа», хотя история принадлежит сценарию и продолжение запрещено. Лучше явная плашка завершённого демо и действие «Начать обычный диалог».
- Стартовый экран стал полезнее, но карточка проекта, стартовые задачи и повторяющийся provider status конкурируют. Оставить один основной следующий шаг, дополнительные сценарии сделать визуально тише.
- Studio: увеличить полезную ширину diff или дать отдельное раскрытие; длинные строки сейчас требуют горизонтального просмотра. Не уменьшать шрифт всего приложения ради этого.

## Практический режим использования

DeepSeek: обзор кода, поиск, небольшой bugfix, правки нескольких файлов с проверкой diff и тестов. Первые задачи выполнять в отдельной Git-ветке/копии проекта. Помощников пока использовать как экспериментальную read-only функцию. Процессы имеют проверки cwd/argv и лимиты, но не OS sandbox. Gemma/vLLM, прочие провайдеры и Windows/Linux этим аудитом не подтверждены.
