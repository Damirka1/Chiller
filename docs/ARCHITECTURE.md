# Архитектура Chiller

Chiller — Kotlin/JVM-приложение с Compose Desktop. Источник истины для общих типов и портов — [Contracts.kt](../contracts/src/main/kotlin/dev/chiller/contracts/Contracts.kt); схемы инструментов и проверки находятся рядом с реализацией в `tools`. Документ описывает устройство, а не будущий API.

| Модуль | Ответственность |
|---|---|
| contracts | Общие типы, порты провайдера, файлов, процессов и журнала |
| agent-core | Цикл модели, контекст, профили, ограничения и помощники |
| providers | Chat Completions, SSE, сборка tool calls и каталог моделей |
| workspace | Чтение, поиск, снимки, точные правки и восстановление |
| runtime | Процессы, ограничение вывода и отмена |
| tools | Схемы и исполнение инструментов, web, диагностика и клиент MCP (stdio) |
| sessions | Журнал, артефакты, восстановление и экспорт |
| design-system | Темы и общие Compose-компоненты |
| app-desktop | Экраны, контроллер, настройки и сборка зависимостей |
| evals | Offline fixtures, сценарии и opt-in live-проверки |

`agent-core` зависит от контрактов, реализации подключаются в desktop/evals. Контракты не зависят от Compose или HTTP DTO. Основные зависимости модулей указаны в их `build.gradle.kts`.

## Инварианты

- Исполняются только полностью собранные и валидные аргументы инструментов.
- Файловые правки проверяют снимок и точные совпадения; конфликт не исправляется нечётким поиском.
- План запрещает запись в проект и процессы; приложение может сохранять свою историю и настройки.
- Независимые чтения могут выполняться параллельно, изменения — последовательно.
- Журнал фиксирует операции и `run.summary`. После сбоя неизвестные побочные эффекты не повторяются автоматически.
- Откат файловых инструментов проверяет текущее состояние. Изменения внешних команд не имеют общей гарантии отката; их обнаружение ограничено размером снимка и хешируемых файлов.
- Лимиты запросов/выходных токенов не являются денежным лимитом API. Неизвестный usage не считается нулевым.
- Проверки путей и cwd не изолируют процессы на уровне ОС.

Сборка и проверка описаны в [CONTRIBUTING](../CONTRIBUTING.md), пользовательские возможности — в [USAGE](USAGE.md).
