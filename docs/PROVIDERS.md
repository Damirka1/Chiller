# Провайдеры

Chiller использует OpenAI-совместимый Chat Completions API. Совпадение формата не гарантирует поддержку tools, vision или reasoning у конкретного сервера. Основные live-проверки выполнялись на DeepSeek (`deepseek-flash`) и на Gemma 4 26B A4B (vLLM 0.31 за HTTPS-шлюзом).

## Подключение

Укажите base URL, точный model ID и ключ в настройках. Для локального сервера обычно используется `http://localhost:8000/v1`; для прямого DeepSeek — `https://api.deepseek.com`. Пути `models` и `chat/completions` добавляются к base URL. Ключ посредника требует адреса этого посредника.

Каталог моделей загружается при старте и смене подключения, доступно ручное обновление. Для удалённого endpoint требуется настроенный ключ, loopback допускает работу без ключа. Последний список сохраняется по endpoint; при ошибке остаётся доступным с признаком устаревания. Смена/удаление ключа очищает кеш его origin. Ответ каталога не доказывает работоспособность генерации или инструментов. Платная проверка подключения запускается явно.

Ключи привязаны к origin. Кнопка «Запомнить ключ» явно сохраняет ключ в системное хранилище: Keychain на macOS, Диспетчер учётных данных на Windows (запись `Chiller/<origin>`, только для текущего пользователя этого компьютера); иначе доступны память процесса и настроенные переменные окружения/.env. Не храните ключи в дополнительных JSON-полях запроса. Подробности — [USAGE](USAGE.md).

## vLLM и шлюзы

Из ответа `/models` Chiller читает:

| Поле | Значение |
|---|---|
| `id` | обязательный ID модели |
| `name` | название в интерфейсе; для «Авто» профиля, если ID ничего не говорит о размере |
| `context_window`, `context_length`, `max_model_len` | окно контекста (первое найденное); без них — 32 768 |
| `max_output_tokens` | подтверждённый предел ответа; отсутствие поля значит «неизвестно» |
| `input_modalities` (или `architecture.input_modalities`) | `image` включает vision в режиме «Авто» |
| `capabilities` | `vision` — если нет `input_modalities`; `reasoning` включает переключатель рассуждений через шаблон чата; `chat_completions`, `image_generation`, `image_editing` |
| `output_modalities`, `supported_endpoints` | модель без текстового вывода или без `/chat/completions` не предлагается для чата; `/images/generations` и `/images/edits` объявляют генерацию и правку |

Отсутствующие поля остаются неизвестными, ID-эвристика используется только тогда.

Рассуждения vLLM приходят в `reasoning` (старые версии и SGLang — `reasoning_content`) и показываются как видимые, но не возвращаются в историю. Для модели с `reasoning` в каталоге переключатель отправляет `chat_template_kwargs: {"enable_thinking": true|false}` в обе стороны: шаблоны Qwen думают по умолчанию. Свой `chat_template_kwargs` в дополнительных полях запроса заменяет этот.

Chiller всегда отправляет `max_tokens`: ограничение ответа — часть бюджета хода и восстановления после обрыва, даже если шлюз советует не передавать его.

Сертификат сервера проверяется по хранилищу JDK и системному хранилищу (Windows-ROOT, связка ключей macOS), поэтому корпоративный CA, которому доверяет ОС, работает без настройки JVM. Проверка не отключается; ошибка TLS приходит как `PROVIDER_TLS_ERROR` без повторов.

`429` с `Retry-After` (секунды или HTTP-дата) пережидается до 120 секунд, ход показывает «Повтор через N с»; больший интервал завершает ход с цифрой сервера. Ошибка, пришедшая SSE-событием `error` после начала ответа, сообщается текстом провайдера (`PROVIDER_STREAM_ERROR`).

Шлюзу стоит отвечать на превышение квоты `429` с `Retry-After` и для `stream: true`: `401` Chiller считает отказом в ключе и не повторяет.

## Картинки

Модель изображений выбирается в «Настройки → Агент → Модель для картинок»: «Авто» берёт первую модель каталога с `image_generation` на том же адресе, «Выкл» убирает инструмент. Запросы идут по OpenAI Images API на тот же адрес и с тем же ключом: `POST /images/generations` (JSON) и `POST /images/edits` (multipart с картинкой). Chiller просит `b64_json` и не загружает картинки по ссылке из ответа; принимает PNG, JPEG и WebP до 64 МиБ. Ошибка квоты или сервера до ответа повторяется до трёх попыток с учётом `Retry-After`; тайм-аут (180 с) не повторяется.

`generate_image` в режиме «План» недоступен, пишет только новый файл (не перезаписывает), с откатом, и не больше четырёх картинок за ход. Референс — картинка проекта или вложение пользователя по `artifact_id`; другие файлы на адрес картинок не отправляются.

## Свой провайдер

«Настройки → Подключение → Добавить свой провайдер» сохраняет название, адрес, переменную окружения/`.env` с ключом, модель по умолчанию и, по желанию, рассуждения и профиль, которые применяются вместе с ним. Запись хранится в `~/.chiller/settings.json` и не попадает в репозиторий или установщик. Ключ читается из переменной при запуске и при сохранении и привязывается к origin этого адреса; ключ, введённый в приложении, переменная не заменяет.

## Профили и протокол

Полный/компактный профиль меняет набор инструментов и параметры работы, а не возможности сервера. Автовыбор по ID — эвристика; настройки можно переопределить. Vision отправляет подготовленные изображения поддерживающим его моделям; флаг поддержки не заменяет проверку сервера.

SSE-адаптер собирает аргументы инструментов до завершения ответа. Частичный вызов не исполняется. Ограниченный повтор stateless-запроса при временной ошибке допустим до первого delta; эффекты инструментов автоматически не повторяются.

Протокольный reasoning/replay хранится отдельно от видимых рассуждений: скрытие текста в UI не должно разрушать необходимую провайдеру историю. Usage сохраняется как сообщил провайдер; отсутствующие показатели остаются неизвестными.

## Длина ответа и обрывы

Запрошенный `max_tokens` не превышает половины окна контекста. Если провайдер отвечает, что значение вне допустимого диапазона (форматы DeepSeek, OpenAI и vLLM), Chiller запоминает его предел для пары адрес + модель и повторяет тот же stateless-запрос один раз. Рассуждения модели расходуют тот же лимит. Обрезанный вызов инструмента не выполняется; модель получает размер лимита и способ дописать файл частями. Обрезанный текст сохраняется, и модель продолжает с места обрыва.

## Проверки

`./gradlew check :evals:offlineSmoke` использует fixtures и локальные сервисы. Первый Gradle-запуск может скачивать зависимости.

В приложении есть свой денежный бюджет задачи (Настройки → Агент → «Денежный бюджет»): лимит в USD, цены за 1M входных и выходных токенов, цена картинки и потолок входных токенов на запрос. Каждая попытка, включая повторы, помощников и картинки, до отправки резервирует худший случай; ответ с известным расходом заменяет резерв фактом, неизвестный исход оставляет резерв. Цены привязаны к адресу, чат-модели и модели картинок, для которых сохранены: с другой моделью бюджет отказывает, пустая цена тоже отказывает. Потолок входных токенов ограничивает и контекст запроса. Итог пишется в `run.summary` (`cost`). Это оценка по вашим ценам, а не счёт провайдера.

Live-проверки RC выполнялись через локальный шлюз с денежным потолком: перед каждым запросом резервируется худшая стоимость по пиковым ценам без скидки за кеш, изображение считается как 16 384 входных токена, после ответа резерв заменяется фактическим расходом, неизвестный исход сохраняет резерв. Сам шлюз — локальный инструмент проверки, он не входит в приложение.

Live-задачи `:evals:liveDeepSeekSmoke`, `:evals:liveEval`, `:evals:liveVisionSmoke`, `:evals:liveImageSmoke` запускаются отдельно с явно настроенным ключом. Они расходуют баланс. Ограничения раундов/выхода не обеспечивают общий долларовый потолок, включая повторы и помощников; задавайте внешний бюджет перед запуском большого набора.
