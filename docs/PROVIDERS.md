# Провайдеры

Chiller использует OpenAI-совместимый Chat Completions API. Совпадение формата не гарантирует поддержку tools, vision или reasoning у конкретного сервера. Основные live-проверки выполнялись на DeepSeek (`deepseek-flash`); Gemma/vLLM пока не проверена на реальном сервере.

## Подключение

Укажите base URL, точный model ID и ключ в настройках. Для локального сервера обычно используется `http://localhost:8000/v1`; для прямого DeepSeek — `https://api.deepseek.com`. Пути `models` и `chat/completions` добавляются к base URL. Ключ посредника требует адреса этого посредника.

Каталог моделей загружается при старте и смене подключения, доступно ручное обновление. Для удалённого endpoint требуется настроенный ключ, loopback допускает работу без ключа. Последний список сохраняется по endpoint; при ошибке остаётся доступным с признаком устаревания. Смена/удаление ключа очищает кеш его origin. Ответ каталога не доказывает работоспособность генерации или инструментов. Платная проверка подключения запускается явно.

Ключи привязаны к origin. На macOS их можно явно сохранить в Keychain; иначе доступны память процесса и настроенные переменные окружения/.env. Не храните ключи в дополнительных JSON-полях запроса. Подробности — [USAGE](USAGE.md).

## Профили и протокол

Полный/компактный профиль меняет набор инструментов и параметры работы, а не возможности сервера. Автовыбор по ID — эвристика; настройки можно переопределить. Vision отправляет подготовленные изображения поддерживающим его моделям; флаг поддержки не заменяет проверку сервера.

SSE-адаптер собирает аргументы инструментов до завершения ответа. Частичный вызов не исполняется. Ограниченный повтор stateless-запроса при временной ошибке допустим до первого delta; эффекты инструментов автоматически не повторяются.

Протокольный reasoning/replay хранится отдельно от видимых рассуждений: скрытие текста в UI не должно разрушать необходимую провайдеру историю. Usage сохраняется как сообщил провайдер; отсутствующие показатели остаются неизвестными.

## Длина ответа и обрывы

Запрошенный `max_tokens` не превышает половины окна контекста. Если провайдер отвечает, что значение вне допустимого диапазона (форматы DeepSeek, OpenAI и vLLM), Chiller запоминает его предел для пары адрес + модель и повторяет тот же stateless-запрос один раз. Рассуждения модели расходуют тот же лимит. Обрезанный вызов инструмента не выполняется; модель получает размер лимита и способ дописать файл частями. Обрезанный текст сохраняется, и модель продолжает с места обрыва.

## Проверки

`./gradlew check :evals:offlineSmoke` использует fixtures и локальные сервисы. Первый Gradle-запуск может скачивать зависимости.

Live-проверки RC выполнялись через локальный шлюз с денежным потолком: перед каждым запросом резервируется худшая стоимость по пиковым ценам без скидки за кеш, изображение считается как 16 384 входных токена, после ответа резерв заменяется фактическим расходом, неизвестный исход сохраняет резерв. Сам шлюз — локальный инструмент проверки, он не входит в приложение.

Live-задачи `:evals:liveDeepSeekSmoke`, `:evals:liveEval`, `:evals:liveVisionSmoke` запускаются отдельно с явно настроенным ключом. Они расходуют баланс. Ограничения раундов/выхода не обеспечивают общий долларовый потолок, включая повторы и помощников; задавайте внешний бюджет перед запуском большого набора.
