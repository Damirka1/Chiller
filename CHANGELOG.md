# Changelog

Все заметные изменения Chiller. Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — [SemVer](https://semver.org/lang/ru/). Release candidate (`-rc.N`) — сборка для проверки перед стабильной версией; установщики у неё получают номер без суффикса (`1.2.0`), этого требуют DMG и MSI.

## [Unreleased]

### Добавлено

- **Проекты в боковой панели:** диалоги сгруппированы по папкам, у проекта цветная монограмма, ветка git, закрепление, «Показать в Finder/проводнике» и «Убрать из списка». Ctrl+P — быстрый переход к проекту, Ctrl+1…9 — новый диалог в проекте.
- **Диалоги без папки:** разговор с веб-поиском и картинками, без доступа к файлам и командам. Его картинки хранятся в данных Chiller.
- **Папка привязана к диалогу:** пока в диалоге нет ходов, чип папки у поля ввода меняет или убирает её на месте; после первого хода другая папка открывает новый диалог.
- Перемещённую папку проекта можно указать заново для всех её диалогов.
- **Задачи в фоне:** при переходе в другой диалог задача продолжается. В списке видно, что она идёт или ждёт ответа, её можно остановить из меню. Одновременно идут до трёх задач, в одной папке — одна.
- **Автопроверка в фоне:** проверка после правок запускается и у диалога в фоне, при ошибке исправление уходит в тот же диалог.
- **Отдельная копия (git worktree):** диалог может работать в своей копии проекта, параллельно с другими задачами в этом проекте; изменения переносятся в проект точным патчем после `git apply --check` или не переносятся вовсе.
- **Продолжить в другой папке:** новый диалог в выбранной папке с черновиком из истории прежнего.
- Перетаскивание папки в боковую панель открывает её как проект; развёрнутость проектов сохраняется между запусками; диалоги с непрочитанным результатом выделены; Shift+Enter в Ctrl+P открывает последний диалог проекта.
- **Уведомления:** о завершении, ошибке, результате проверки и вопросе агента в диалоге, который сейчас не открыт; клик открывает диалог.

### Исправлено

- Задача, остановленная во время вопроса агента, при открытии показывается остановленной, а не прерванной.
- На Windows вместо имени папки показывался полный путь; «Открыть в Finder» в настройках на Windows называется «Показать в проводнике».

## [1.2.1] — 2026-10-21

Работа с инструментами для небольших моделей по живым замерам на Gemma 4 26B A4B (vLLM, компактный профиль, с рассуждениями). Рассуждения теперь возвращаются модели внутри хода. Результаты и ошибки правок подсказывают следующий шаг, чтение подстраивается под окно контекста, запас на рассуждения больше. Добавлены eval-задачи `tool-*` и `hard-*`.

### Добавлено

- **`append_file`:** длинный файл пишется частями — `create_file`, затем `append_file` со `snapshot_id` предыдущего шага; существующие строки не меняются. `create_file` теперь возвращает `snapshot_id`.
- В компактном профиле `append_file`, `delete_file`, `move_file` и `create_directory`: раньше модель удаляла и переносила файлы через командную строку, без отката и только с разрешением на процессы.
- **Сэмплинг Gemma:** модели Gemma (по ID или названию из каталога) получают рекомендованные Google temperature 1.0, top_p 0.95, top_k 64 вместо 0.2 компактного профиля. Выбор temperature в настройках и дополнительные поля важнее; `null` в дополнительных полях убирает поле по умолчанию.
- Eval-задачи `tool-*` (правка в конце файла, экранирование, табы, замена всех вхождений, цепочка правок, большой файл, длинный вывод, удаление и перенос, запись частями) и `CHILLER_EVAL_EXTRAS` для A/B по полям запроса; поля запроса пишутся в отчёт.
- **Сложные eval-задачи `hard-*`** для моделей, которые проходят короткие. Шесть задач: фича через шесть модулей по спецификации, два связанных бага среди файлов-приманок, восемь по-разному записанных форматов дат в файле на 450 строк, реализация по спецификации со скрытыми случаями, тесты, которые должны поймать семь мутантов, и настройка, прослеженная через три слоя конфигурации. Для них лимит раундов — 24, как в приложении.

### Исправлено

- **Рассуждения vLLM возвращаются модели внутри хода.** Раньше Gemma 4 и Qwen 3 с рассуждениями забывали после каждого вызова инструмента, что собирались делать, хотя Gemma 4 требует сохранять мысли между вызовами одного хода. Теперь рассуждения уходят с сообщениями модели в `reasoning_content`; рассуждения прошлых ходов шаблоны чата убирают сами. На 18 задачах с Gemma 4 (компактный профиль, с рассуждениями) все задачи прошли и до, и после. Генерируемых токенов стало меньше на 45%, времени уходит на 37% меньше, раундов только для `update_plan` — вдвое меньше.
- Запрет на запуск процессов теперь подсказывает, что делать вместо этого: читать файлы и назвать пользователю команду для проверки.
- **Снимки после правок.** Результат `create_file`, `replace_text`, `append_file` и других правок начинается с `snapshot_id`, так же как у `read_file`, а хеши из него убраны. Раньше модель брала `id` правки или `afterHash` вместо `snapshotId`, стоявшего последним. Неизвестный или чужой `snapshot_id` в ответ получает действующий снимок файла, если он уже есть, а не просьбу перечитать файл.
- **Чтение по размеру окна.** Одно чтение `read_file` показывает около 5% окна контекста модели: 200 строк при 32k, около 740 при 128k. Раньше Gemma читала файл на 471 строку кусками по 200 и тратила по два раунда на каждую правку.
- `create_file` поверх существующего файла подсказывает, что делать вместо этого; при различии только в пробелах на пустых строках ошибка называет эти строки. Если длинный `old_text` расходится с файлом, ошибка называет первую несовпавшую строку и показывает обе версии.
- **Запас на рассуждения 12288 токенов вместо 4096.** На задаче со сложной спецификацией рассуждения Gemma обрезались 8 раз за 4 попытки, и каждый раз терялось 80–115 с. С новым запасом обрезок нет, а попытка занимает около 150 с вместо 300–600. Это верхняя граница: короткие ответы не становятся длиннее.
- `replace_text` не находил `old_text`, скопированный до конца файла вместе с последним переводом строки.
- Ошибки правок объясняют, что исправить: при различии только в пустых строках — править по частям, при двойном экранировании — писать `\n` один раз, при префиксах `12 | ` — убрать их; `MATCH_COUNT_MISMATCH` объясняет смысл `expected_count`, `UNOBSERVED_RANGE` называет строки для чтения.
- Строки, прочитанные под разными снимками одного и того же содержимого, засчитываются вместе: правка после чтения файла частями не требует перечитывания.
- Ошибки аргументов называют аргумент и ожидаемый тип; вызов несуществующего инструмента — `UNKNOWN_TOOL` со списком доступных.
- Длинный вывод завершившегося процесса приходит началом, строками с ошибками из пропущенной середины и концом, а не первыми 16 КБ.
- Обрезанный `read_file` сообщает показанные строки и `next_start_line`; у `search_text`/`list_files` и параметров правок появились описания (`expected_count` модель больше не передаёт без нужды).
- Если рассуждения заняли весь лимит ответа и ничего не вышло, пустой ответ не сохраняется, а следующий шаг идёт без рассуждений.
- Второй одинаковый неудачный вызов получает предупреждение до того, как третий завершит ход; подсказка после обрыва ответа называет инструмент, который есть в профиле.
- Финальный ответ вместе с закрывающим `update_plan` завершает ход без лишнего раунда, как и закрывающий `update_plan` сразу после напоминания о плане, если все шаги выполнены.

### Известные ограничения

- Замеры сделаны на одном шлюзе (Gemma 4 26B A4B, vLLM 0.31) небольшими прогонами; другие модели на vLLM вживую не проверялись.
- Компактный профиль и сэмплинг Gemma выбираются автоматически по ID или названию модели из каталога. Псевдоним без «Gemma» в названии получает полный профиль: выберите компактный в «Настройки → Агент → Профиль модели».
- Установщики не подписаны: на macOS первый запуск — правый клик → «Открыть», на Windows SmartScreen может попросить подтверждение.
- Проверки путей и рабочей папки процессов — не песочница ОС.

## [1.2.0] — 2026-10-19

Стабильная версия 1.2. Проверена вживую на Gemma 4 26B A4B (vLLM за HTTPS-шлюзом): генерация и правка картинок, свой провайдер с ключом в системном хранилище, денежный бюджет задачи, память длинного диалога и защита от зацикливания и выдуманных данных.

### Добавлено

- **Каталог моделей сообщает больше:** окно контекста из `max_model_len` (так его отдаёт vLLM), vision из `input_modalities`/`capabilities`, reasoning из `capabilities`. «Авто» vision доверяет каталогу раньше ID, а «Авто» профиль смотрит на название, если ID ничего не говорит о размере: псевдоним `quasar` с названием «Gemma 4 26B A4B» получает компактный профиль и vision.
- **Рассуждения vLLM:** поле `reasoning` показывается как видимые рассуждения и не возвращается в историю; для модели с `reasoning` в каталоге переключатель рассуждений передаёт `chat_template_kwargs.enable_thinking`.
- Live eval читает каталог, пропускает задачи без нужных профилю инструментов (SKIP) и помечает сбои провайдера как ERROR, а не как провал модели.
- **Генерация и правка картинок:** инструмент `generate_image` через модель изображений провайдера (OpenAI Images API: generations и multipart edits). Картинка сохраняется новым файлом с превью, откатом и записью в журнал; референс — картинка проекта или вложение. Модель выбирается в «Настройки → Агент → Модель для картинок» (Авто по каталогу, Выкл или конкретная). Live-проверка `:evals:liveImageSmoke` и eval-задача `generate-image`.
- **Свой провайдер:** название, адрес, переменная с ключом, модель, рассуждения и профиль по умолчанию; хранится только в локальных настройках, ключ из `.env` привязан к адресу провайдера.
- С включёнными рассуждениями ответ получает 4096 токенов запаса сверх лимита: рассуждения тратят тот же `max_tokens`.
- **Денежный бюджет задачи:** лимит USD по вашим ценам; резерв худшего случая перед каждой попыткой (повторы, помощники, картинки), привязка цен к модели, отказ вместо подсчёта по чужим ценам, итог в `run.summary`.
- **Память длинного диалога:** при сжатии контекста сохраняются ограничения из всех сообщений пользователя (с номером сообщения), открытые шаги плана и исходный запрос.
- **Помощники ищут в интернете**, если у хода он разрешён; `wait_agents` ждёт завершения помощника, а не каждого его шага.
- **План доводится до конца:** финальный ответ при открытых шагах получает до двух напоминаний; статус `skipped` с причиной; незакрытый план виден в итоге хода.
- Модели сообщается, что она умеет в этой сессии (картинки, интернет, помощники, процессы), сегодняшняя дата и система пользователя с подсказками запуска команд.
- Окно запоминает размер и развёрнутость между запусками.
- Eval: многоходовые сценарии (смена требований, правка пользователя, перезапуск, сжатие контекста), задачи на закрытие плана и на отказ выдумывать данные.
- **Ключи на Windows сохраняются между запусками:** кнопка «Запомнить ключ» кладёт ключ в Диспетчер учётных данных Windows (запись `Chiller/<origin>`, только для текущего пользователя этого компьютера), как Keychain на macOS. Проверка `:app-desktop:windowsCredentialSmoke` создаёт, читает, обновляет и удаляет одноразовую запись.

### Исправлено

- **Корпоративный CA:** сертификат проверяется по хранилищу JDK и системному (Windows-ROOT, связка ключей macOS). Раньше сервер, которому доверяет Windows, давал «Provider connection failed» с тремя повторами; теперь он работает, а ошибка TLS называется `PROVIDER_TLS_ERROR` и не повторяется.
- **`Retry-After`** учитывался только до 2 секунд, и квота шлюза (`429`, `Retry-After: 60`) обрывала ход за две секунды. Теперь ожидание до 120 секунд с уведомлением «Повтор через N с»; больший интервал завершает ход с цифрой сервера.
- Ошибка, пришедшая SSE-событием посреди ответа, сообщается текстом провайдера, а не как оборванный поток.
- **Выдуманные данные:** `web_fetch` помечает страницы, которые рисуются скриптами и не содержат данных; пустой поиск без пометки «ничего не найдено» — ошибка `SEARCH_UNAVAILABLE`; в результатах поиска снова есть сниппеты; промпт требует брать факты только из результатов инструментов.
- **Зацикливание:** повторы считаются по инструменту, аргументам и результату; одинаковый результат даёт напоминание, затем раунд без инструментов с честным ответом; последний разрешённый шаг тоже отвечает, а не обрывается ошибкой.
- Отсутствующая программа даёт `EXECUTABLE_NOT_FOUND` с подсказкой для ОС (на Windows — `cmd /c start`), а не безликое `TOOL_FAILED`.
- Модель изображений из каталога больше нельзя выбрать для чата: выбор модели показывает только модели с текстовым выводом и `/chat/completions`.
- Gradle на JDK старше 21 сразу сообщает, что нужен JDK 21+, а не падает при запуске тестов или eval с `UnsupportedClassVersionError`.

## [1.2.0-rc.3] — 2026-10-18

Последний кандидат перед 1.2.0: смена модели внутри диалога и доработки настроек.

### Изменено

- **Смена модели больше не начинает новый диалог.** Выбранная в меню модель того же провайдера продолжает текущий диалог со следующего сообщения; в журнал пишется `session.model`. Служебное reasoning протокола отправляется обратно только модели, которая его написала, поэтому ответы прежней модели уходят новой как обычный текст. Смена адреса провайдера в настройках по-прежнему начинает новый диалог, чтобы история не уходила другому сервису без явного решения.
- Статус подключения больше не висит в «не проверено», хотя всё работает: первый ответ модели подтверждает подключение без отдельного запроса, полученный список моделей показывает «сервер отвечает», а до этого статус называется «настроено».
- Страница настроек появляется плавным сдвигом вместе с боковой панелью; рядом с «Подключением» видна точка статуса, внизу панели — версия и переключатель темы; ↑/↓ переключают разделы.
- Навигация настроек открывается в боковой панели вместо списка диалогов, с плавным сдвигом; странице настроек достаётся вся ширина. Без боковой панели (узкое окно) список разделов остаётся на странице.

## [1.2.0-rc.2] — 2026-10-18

Исправления по итогам проверки 1.2.0-rc.1.

### Добавлено

- **Встроенный ripgrep 14.1.1** в установщиках: официальные архивы с проверкой SHA-256 и их лицензиями; поиск работает без `rg` в системе. Перед сборкой DMG/MSI готовое приложение проверяется поиском по путям с кириллицей при пустом PATH.
- **Поиск внутри больших вложений и сохранённых результатов:** `read_artifact` принимает `query` и возвращает совпавшие строки с номерами и смещениями. Раньше большой лог приходилось листать вслепую по 16 КБ.
- **Просмотр памяти задачи:** когда длинный ход сокращается, видно, какие выдержки остались в контексте.
- **Диагностика окружения** в «О программе»: ripgrep (встроенный или из PATH), Git и Python 3 по команде `--version`, без сети; в «Подключении» — отдельно ключ, каталог моделей и проверка генерации.
- **Собственный заголовок окна на Windows:** системная полоса с заголовком и меню убрана, интерфейс начинается от верхнего края, как на macOS. Кнопки свернуть/развернуть/закрыть, привязка окон (Snap), перетаскивание и двойной щелчок остаются системными. Меню переехало в кнопку «≡» в панели инструментов, сочетания Ctrl+N, Ctrl+O, Ctrl+, , Ctrl+. и Ctrl+Enter работают как раньше. Нужна среда JetBrains Runtime, с которой теперь собирается установщик для Windows; на другой JVM остаётся обычная рамка окна.
- **«О программе»:** полная версия с суффиксом (`1.2.0-rc.2`) и пометкой предварительной версии, номер сборки CI и дата коммита, ссылка на коммит, автор и лицензия, кнопка «Скопировать сведения» для отчётов об ошибках (без пути к данным). В установщиках указан издатель (Damirka1) и copyright.
- **Сведения о сторонних компонентах** внутри приложения: лицензии из POM каждой библиотеки, файлы LICENSE/NOTICE из их JAR и текст Apache 2.0.

### Изменено

- После обрыва ответа по лимиту агент получает точный размер лимита и способ дописывать файл частями; задача останавливается только после двух обрывов подряд без продвижения.
- Расход токенов сохраняется и при обрезанном ответе, неполные суммы помечаются; известный расход возвращает неиспользованный резерв бюджета.
- Длинный текущий ход сокращается целыми обменами с инструментами, с сохранением исходного запроса, последнего обмена и неизвестных исходов. Разовая нехватка контекста больше не запоминается как предел модели.
- Готовый план модели показывается внутри карточки итога хода, а не отдельной карточкой.
- Остановка по 10-минутному пределу задачи называется так, а не «отменой пользователем».
- Релизный workflow сначала проверяет помеченный коммит на Linux, macOS и Windows и только потом собирает установщики.
- При запуске из исходников на macOS в Dock показывается «Chiller», а не «java».

### Исправлено

- Подсказки сочетаний клавиш на Windows и Linux показывают Ctrl, а не ⌘.
- Восстановление статуса сессии после `run.truncated`.
- Локальная сборка пакета не замечала изменений в подготовленных ресурсах и могла оставить устаревшие уведомления или ripgrep.

### Известные ограничения

- Задача ограничена 10 минутами даже при «Без лимита» шагов и бюджета; после остановки её можно продолжить.
- Установка на чистую Windows не проверялась; Windows ARM64 текущая упаковка не поддерживает.
- Установщики не подписаны и не нотаризованы; обновление RC → stable не проверялось.
- Gemma на vLLM не проверена вживую.

## [1.2.0-rc.1] — 2026-10-18

Первый release candidate ветки 1.2: профили для небольших моделей, проверяемый итог хода, vision и работа с длинными ответами.

### Добавлено

- **Профили моделей.** «Полный» (33 инструмента) и «Компактный» (13 инструментов, пошаговый промпт, один вызов за шаг) для моделей на 4–30B; «Авто» выбирает по ID модели. В компактном профиле — карта проекта в контексте и поиск определений `find_symbols`. Замер на DeepSeek V4.1 Flash, 14 задач: раундов 67 → 56, промпт ~235k → ~146k токенов при том же результате.
- **Итог хода из фактов.** Карточка в конце хода собирается из журнала: изменённые файлы, команды с кодами выхода, показанные файлы. Отдельно подсвечиваются упавшая и не перезапущенная проверка, непрочитанный результат, неприменившаяся правка и ответ «тесты прошли», когда проверок не было.
- **Изменения вне инструментов агента.** Файлы, которые за ход изменили команды или вы сами, показываются отдельно: откат хода их не вернёт.
- **Откат целого хода** одной кнопкой, с точным восстановлением файлов; повторный откат и перезапуск приложения это учитывают.
- **Автопроверка.** После правок запускается команда проверки проекта; упавший вывод возвращается агенту, число попыток настраивается.
- **Сравнение моделей** на встроенных eval-задачах прямо в приложении: успех, время, токены, повторные чтения и неудачные правки.
- **Vision.** Картинки из буфера и файлов уходят моделям, которые их понимают (проверено вживую на DeepSeek V4.1 Flash): уменьшаются до 1568 px, отправляются только с последними сообщениями.
- **«Максимум модели»** для длины ответа: Chiller узнаёт предел модели из ответа провайдера (у DeepSeek Flash — 384k) и запоминает его. Для бюджета задачи и числа шагов — вариант «Без лимита» (со страховкой 500 шагов).
- **Живой чек-лист плана** под сообщениями; **Shift+Tab** переключает «План» и «Изменения».
- **Мгновенная вставка:** карточка вложения появляется сразу, кодирование идёт в фоне; большой текст становится файлом.
- **Копирование таблиц** из ответа: в Excel/Numbers/Google Sheets вставляются таблицей, в текст — колонками.
- Метрики потерь в eval-отчётах, живые проверки vision, автоматическая загрузка каталога моделей провайдера, лицензия Apache 2.0.

### Изменено

- Настройки агента применяются со следующего сообщения (раньше — со следующего диалога); история сохраняется.
- Ответ, обрезанный лимитом длины, больше не обрывает задачу: обрезанный вызов не выполняется, а агент продолжает, записывая большой файл частями. После остановки по лимиту шагов есть кнопка «Продолжить».
- Ошибки провайдера с кодом 400 показывают его собственное сообщение, а не только «HTTP 400».
- Кодирование больших вставленных картинок в 10–20 раз быстрее (8K «шум»: 5,4 с → 0,27 с), подготовленные изображения не пересчитываются на каждом раунде.

### Исправлено

- Поиск символов и карта проекта работали только в проектах до ~1500 файлов.
- Отмена удалённого файла падала с `NoSuchFileException`.
- Чат прыгал при прокрутке к уже показанной картинке; широкая картинка наезжала на подпись; полоса загрузки заходила на боковую панель.
- Сравнение моделей теряло частичные результаты при остановке и «зависало», если остановить его сразу после старта.
- Результат автопроверки мог попасть в другой диалог после переключения проекта.
- Шесть тестов молча не запускались; нестабильные тесты на Windows и Linux исправлены.

### Известные ограничения

- Gemma на vLLM ещё не проверена вживую — замеры сделаны на DeepSeek V4.1 Flash.
- Установщики не подписаны: на macOS первый запуск — правый клик → «Открыть», на Windows SmartScreen может попросить подтверждение.
- Проверки путей и рабочей папки процессов — не песочница ОС.
